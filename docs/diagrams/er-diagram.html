Entity–Relationship Diagram

Two mirror-image model families — Customers and Products — each a tree rooted at an upload, plus a set of shared operational tables that no foreign key ties to anything (by design). Every child relation is onDelete: Cascade: delete a root and its whole subtree goes with it.

Shared operational tables

No foreign keys reach these. They serve both flows and reference runs by soft id (e.g. CleanupRun.importRunId, StoreLock.ownerId) rather than a Prisma relation — precisely so a cascading delete on one flow can never wipe an audit record or strand a lock.
